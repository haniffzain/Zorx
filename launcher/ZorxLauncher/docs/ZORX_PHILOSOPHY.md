# Zorx Philosophy

Zorx treats Android as the application platform and the desktop shell as a coherent
workspace, not as a decorative launcher layer.

- Native first: use real Android tasks and freeform capabilities.
- Honest status: distinguish implemented UI from verified native behavior.
- Direct manipulation: windows respond predictably to desktop controls.
- One lifecycle: visual and Android task state must not silently diverge.
- Modularity: desktop policy, rendering and Android integration have clear boundaries.
- Responsiveness: coalesce expensive native updates without degrading input.
- Compatibility: preserve stable user interactions while infrastructure evolves.
- Extensibility: support multi-window, widgets and future workspace services.

Documentation claims must be traceable to development and state whether behavior is
spatial-only, native, partial or complete.
